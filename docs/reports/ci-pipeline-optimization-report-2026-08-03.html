변경 불변 조건

최적화는 release 안전 경계를 약화시키지 않는 범위에서만 승격했습니다.

fail-closed
  • protected main에서만 production release
  • test runner에 Docker socket·GPU·production credential 없음
  • Critical / High SAST와 secret 1건도 gate 차단
  • immutable Git SHA tag와 digest-pinned deploy
  • PostgreSQL·rust_socket·paper-only boundary health 확인
  • preflight 실패 또는 health 실패 시 rollback 기준 유지

06 · Reusable blueprint

다른 저장소에 이식하는 순서

특정 프로젝트의 숫자를 복사하지 말고, workload 경계·ownership·측정 scope만 저장소에 맞게 바꾸면 됩니다.

portable pattern

1. 변경 경로 gate

docs-only와 code-sensitive를 명시적으로 분리합니다.

.ci-code-paths: &code_paths
  - src/**/*
  - package-lock.json
  - .gitlab-ci.yml

rules:
  - if: '$CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH'
  - changes: *code_paths
  - changes: *doc_paths
    when: never

2. cache ownership

writer 하나, consumer는 pull-only로 유지합니다.

cache:
  key:
    files: [package-lock.json]
    prefix: node-npm-v2
  policy: pull
# node-static만 pull-push writer

3. memory-aware scheduler

reservation과 headroom을 먼저 계산하고 병렬도를 clamp합니다.

reservation = child_peak_p95 + safety_margin
parallel = clamp(requested, 1, budget / reservation)
# failure/OOM이면 parallel=1로 rollback

4. evidence 최소화

성공 artifact는 작게, 실패 artifact는 debugging 가능하게 남깁니다.

success → report.json only
failure → report.json + screenshots/logs
TTL: test 14d · UI 7d · audit 90d

적용 checklist

승격 전 반드시 같은 표에 결과를 남깁니다.

  • runner별 memory/socket/GPU/concurrency 측정
  • job duration·queue·retry·RSS·OOM·CPU/I/O 수집
  • cache key·writer·consumer·compressed size·TTL 기록
  • cold와 warm을 각각 실행하고 median/p95 비교
  • security finding fingerprint와 test count 보존
  • protected main의 release/health/rollback gate 재검증
  • 변경마다 hypothesis·acceptance·rollback·owner 기록
  • Graphify와 작업 기록 문서 갱신
